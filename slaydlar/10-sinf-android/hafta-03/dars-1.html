Istalgan vaqtda eski holatga bitta buyruq bilan qaytish mumkin.

Markazlashgan (SVN) vs Tarqoq (Git)

O'zingizni tanishtiring: git config

Mualliflik sozlamalari

Git har bir yozilgan kod ostida kim turganini bilishi kerak. Buning uchun bir marta buyruq kiritiladi:

Kiritilgan parametrlarni ko'rish uchun:

01

Gitning 3 Asosiy Holati

Working Directory, Staging Area va Repository (.git)

Git qanday ishlaydi? (3 ta maydon)

Repozitoriy ochish: git init

Yangi ombor yaratish

Istalgan loyiha papkasiga kirib, terminalda yoziladi:

git init

Natijada papka ichida yashirin .git/ papkasi paydo bo'ladi.

Muhim ogohlantirish!

.git/ papkasi — Gitning barcha xotirasi. Agar siz uni o'chirib yuborsangiz, loyihaning butun o'tmishi bir zumda yo'qoladi!

Oddiy fayllar qoladi, lekin commitlar tarixi o'chib ketadi.

Fayllar holati: git status

Qizil rang (Untracked / Modified)

Untracked files:
    (use "git add <file>...")
        MainActivity.kt

Git fayl borligini ko'rdi, lekin u hali sahnaga kiritilmagan.

Yashil rang (Changes to be committed)

Changes to be committed:
    new file:   MainActivity.kt

Fayl git add qilindi va suratga olinishga tayyor holatda turibdi.

Sahnaga olib chiqish: git add

Bitta faylni qo'shish

Faqat aniq bir fayl o'zgarishini sahnaga chiqarish:

git add MainActivity.kt

Boshqa fayllar Working Directory'da qoladi.

Barcha o'zgarishlarni qo'shish

Loyiha papkasidagi hamma o'zgargan va yangi fayllarni qo'shish:

git add .

Nuqta (.) barcha joriy papka fayllarini bildiradi.

Birinchi commitni amalga oshirish qadamlari

1

Loyiha papkasini ochish

Terminalda loyiha papkasiga kiring: cd MyAndroidApp

2

git init

Omborni ishga tushiring va .gitignore mavjudligini tekshiring.

3

git add .

Barcha kerakli manba kodlarini sahnaga (Staging Area) olib chiqing.

4

git commit -m "..."

Ma'noli izoh bilan tarixga yozing: git commit -m "Initial commit"

Commit xabarlari madaniyati (Commit Conventions)

Yomon commit xabarlari

"kod yozdim", "tuzatish", "asdasd", "oxirgi versiya"

Bir oydan keyin qaysi commit nima qilganini hech kim topolmaydi!

Professional format

feat: Foydalanuvchi profil ekrani qo'shildi

fix: Login tugmasi bosilmaslik xatosi tuzatildi

docs: README fayliga qo'llanma kiritildi

Tarix bo'ylab sayohat: git log

Batafsil tarix: git log

commit a1b2c3d4e5f6... (HEAD -> main)
Author: Ali Valiyev <ali@x.uz>
Date:   Sun Oct 4 14:20:00 2026

    feat: Login sahifasi yaratildi

Har bir commitning 40 xonali unikal xeshi (SHA-1) ko'rinadi.

Ixcham ko'rinish: --oneline

git log --oneline --graph
* a1b2c3d feat: Login sahifasi
* e4f5g6h docs: README yaratildi
* 9z8y7x6 Initial commit

Katta loyihalarda tarixni tez ko'rish uchun eng qulay usul.

02

Android Loyihalari va .gitignore

Repozitoriyni ortiqcha og'ir kesh va shaxsiy parollardan tozalash

.gitignore faylining filtri qanday ishlaydi?

Nega local.properties Gitga kirmaydi?

Shaxsiy SDK yo'li

sdk.dir=/Users/ali/Library/Android/sdk

Agar siz bu faylni Gitga yuklasangiz, do'stingiz (masalan, Windows ishlatuvchi) kodni yuklab olganda uning Android Studio'si ishlamay qoladi!

Maxfiy kalitlar

Ko'pincha API kalitlar va parollar shu yerda saqlanadi.

Uni ochiq repoga yuklash xavfsizlikka jiddiy putur yetkazadi.

Shuning uchun u doimo .gitignore ichida bo'ladi.

Darsda o'rganilgan asosiy terminal buyruqlari

Sozlash va Boshlash

git config --global user.name "..." — ismni kiritish

git init — yangi ombor ochish

git status — fayllar holatini tekshirish

Sahnaga chiqarish va Tarix

git add <fayl> (yoki git add .) — sahnaga olish

git commit -m "izoh" — tarixga muhrlash

git log --oneline — tarixni ko'rish

Tezkor bilim sinovi

Gitda o'zgartirilgan faylni doimiy omborga yozishdan oldin qaysi maydonga chiqarish shart?
Faqat Working Directory da qoldirish kifoya
Staging Area (git add orqali)
To'g'ridan-to'g'ri internetga yuklash
Faylni o'chirib qayta yaratish

Sinfdagi amaliy laboratoriya ishi

1. Repozitoriy ochish

Terminalda AndroidNotes papkasini oching, git init qiling va README.md faylini commit qiling.

2. .gitignore sinovi

.gitignore fayli yaratib, *.log deb yozing. Yangi log fayl yaratganda uning kuzatilmasligini tekshiring.

Darsning 4 oltin qoidasi

1. Har doim statusni tekshiring

Commit qilishdan avval doim git status buyrug'i bilan sahnani tekshiring.

2. Ma'noli commit yozing

Commit xabarlari nima qilinganini aniq ifodalasin (masalan, feat: ...).

3. .gitignore ni unutmang

Ortiqcha keshlar va parollarni aslo Gitga yuklamang.

4. Tez-tez commit qiling

Katta ish tugashini kutmay, har bir kichik mantiqiy blokdan so'ng commit qiling.

Uyga vazifa va anons

1. Gitni sozlash

O'z kompyuteringizda git config orqali ism va pochtani kiritish.

2. 3 ta ketma-ket commit

Yangi loyiha ochib, kamida 3 ta ma'noli commit qilish va git log ni ko'rish.

Keyingi dars: Git tarmoqlari (Branch), birlashtirish (Merge) va to'qnashuvlarni (Conflict) yechish!
