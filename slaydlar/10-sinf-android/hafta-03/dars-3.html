Lokal Git va Masofaviy GitHub Arxitekturasi

01

Remote Repozitoriy va Push/Pull

Lokal Gitni GitHub bilan bog'lash va sinxronlash

Public vs Private: Qaysi birini tanlaymiz?

Public (Ochiq ombor)

Butun dunyo kodingizni ko'ra oladi va undan o'rganishi mumkin.

Dasturchining bilimi, yozgan kodi tozaligi va tajribasining eng ishonchli isboti.

Barcha o'quv loyihalarimiz uchun tavsiya etiladi!

Private (Yopiq ombor)

Faqat siz va siz taklif qilgan jamoa a'zolariga ko'rinadi.

Tijoriy dasturlar, buyurtmachi loyihalari va maxfiy ma'lumotlar uchun ishlatiladi.

Masofaviy manzilni ulash: git remote

Serverni 'origin' nomi bilan ulash

git remote add origin https://github.com/user/app.git

Bu buyruq lokal Gitga «mening asosiy serverim mana shu yerda» deb tushuntiradi.

Ulangan manzilni tekshirish

git remote -v

Natijada fetch va push uchun qaysi havola o'rnatilgani ko'rinadi.

Kodni internetga yuklash: git push

Birinchi marta yuklash (-u flagi)

git branch -M main
git push -u origin main

-u (upstream) flagi lokal main tarmog'ini serverdagi origin/main bilan mustahkam bog'laydi.

Keyingi har safar:

git push

Shunchaki bitta so'z yozish kifoya — barcha yangi commitlar avtomatik tarzda GitHub'ga uchadi!

Loyihani GitHub'ga chiqarishning 4 qadami

1

GitHub'da repo ochish

github.com da "New repository" tugmasini bosing va nom bering (masalan, my-android-app).

2

git remote add origin

Berilgan HTTPS havolasini terminalda lokal loyihangizga ulang.

3

git push -u origin main

Barcha commitlar va o'zgarishlar tarixini GitHub serveriga yuklang.

4

Sahifani yangilash

Brauzerni yangilang — kodingiz butun dunyo uchun ochiq holda paydo bo'ldi!

O'zgarishlarni yuklab olish: git pull

Jamoa ishini qabul qilish

git pull origin main

Do'stingiz yoki hamkasbingiz GitHub'ga yangi kod yuklagan bo'lsa, uni o'z kompyuteringizga ko'chiradi.

git clone (Noldan olish)

git clone https://github.com/user/app.git

Yangi kompyuterda tayyor loyihani butun tarixi bilan bir zumda yuklab olish.

README.md va Portfolio San'ati

Loyiha yuzi, Markdown sintaksisi va professional ko'rinish

README.md: Repozitoriy tashrif qog'ozi

Birinchi taassurot

Har qanday odam (ayniqsa HR va texnik rahbar) loyihangizga kirganda birinchi bo'lib README ni o'qiydi.

Bo'sh README — egasi o'z ishiga mas'uliyatsiz ekanidan darak beradi.

Nimalar bo'lishi shart?

1. Ilova nima vazifa bajaradi (1-2 jumla);

2. Ekran skrinshotlari yoki GIF animatsiya;

3. Ishlatilgan texnologiyalar (Kotlin, Compose, Room);

4. Ilovani o'rnatish va ishga tushirish qadamlari.

03

Issues va Jamoaviy Hamkorlik

Vazifalar taxtasi va hamkorlarni repozitoriyaga taklif qilish

GitHub Issues: Muammo va vazifalar boshqaruvi

Issues nima?

Loyiha ichidagi vazifalar (To-Do) va xatolar (Bug report) ro'yxati.

Jamoada har bir vazifa alohida Issue sifatida ochiladi va unga mas'ul shaxs biriktiriladi.

Avtomatik yopish sehrgarligi

git commit -m "fix: login crash muammosi tuzatildi, fixes #1"

Agar commit xabariga fixes #1 deb yozib push qilsangiz, GitHub 1-raqamli issue'ni avtomatik ravishda yopadi!

Collaborators: Jamoa a'zolarini taklif qilish

Hamkor qo'shish tartibi

1. Repozitoriyda Settings > Collaborators bo'limiga kiring;

2. "Add people" tugmasini bosing;

3. Do'stingizning GitHub username yoki elektron pochtasini yozing.

Hamkorlik huquqlari

Taklifni qabul qilgan hamkor kodingizni bevosita o'zgartirishi va push qilishi mumkin.

Birgalikda katta loyihalarni bajarishning eng qulay usuli.

Android Studio'dan to'g'ridan-to'g'ri ulash

GitHub akkauntni ulash

Android Studio menyusi:

Settings > Version Control > GitHub

"Log In via GitHub" tugmasi bosiladi va brauzer orqali bir marta tasdiqlanadi.

Share Project on GitHub

Yuqori menyu: Git > GitHub > Share Project on GitHub

Android Studio o'zi repozitoriy ochadi, commit qiladi va push qilib beradi!

GitHub sirlari (Kartalarni bosing)

Yashil katakchalar

bosing

Contributions: Har bir push qilgan commit profilingizda yashil katakcha bo'lib muhrlanadi. Faol dasturchi profili doim yashil bo'ladi!

Token xavfsizligi

bosing

PAT: GitHub parollar o'rniga Personal Access Token (PAT) ishlatadi. Uni hech qachon ochiq kodda qoldirmang!

Star va Fork

bosing

Reyting: Loyihangiz yoqsa odamlar unga Yulduzcha (Star) bosadi yoki o'ziga nusxalab oladi (Fork).

Bugungi dars buyruqlari spravochnigi

Ulash va Yuklash

git remote add origin <url> — serverni ulash

git remote -v — manzillarni ko'rish

git push -u origin main — birinchi push

git push — keyingi commitlarni jo'natish

Qabul qilish va Klonlash

git pull origin main — o'zgarishlarni yuklash

git clone <url> — yangi kompyuterga ko'chirish

Sinfdagi laboratoriya amaliyoti

1. Loyihani GitHub'ga yuklash

GitHub'da repo oching, lokal Android loyihangizni unga ulang va git push qiling.

2. README va Issue

README fayli yozing, bitta Issue oching va uni maxsus commit bilan yoping.

Darsning 4 oltin qoidasi

1. Kodingizni bulutda saqlang

Har kuni ish tugagach, commitlarni GitHub'ga push qilishni odat qiling.

2. Chiroyli README yozing

Loyihangiz yuzi go'zal bo'lsin: skrinshotlar va aniq qo'llanma bo'lishi shart.

3. Rejalarni Issues da yuriting

Kallangizdagi fikrlarni emas, aniq vazifalarni ro'yxatga oling.

4. Parollarni repoga yuklamang

.gitignore ni doim tekshirib, xavfsizlikka e'tibor bering.

Uyga vazifa va anons

1. GitHub'ga yuklash

Android loyihangizni GitHub'ga yuklang va README faylini boyiting.

2. 2 ta Issue ochish

Yangi funksiyalar bo'yicha masalalar oching va havolani mentorga jo'nating.

Keyingi hafta: GitLab, Bitbucket platformalari, Pull Request va CI/CD avtomatlashtirish!
