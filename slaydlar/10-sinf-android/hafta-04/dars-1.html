03

Merge Request va Pipeline

Kodni tekshirib qo'shish va jarayonni avtomatlashtirish

Bir tushuncha, ikki nom

Pull Request (PR)

Branchdagi o'zgarishni asosiy branchga qo'shish uchun rasmiy so'rov.

Merge Request (MR)

Aynan shu mazmun, faqat GitLab shunday ataydi.

Code Review: 4 qadam

1. MR ochiladi

Branch push qilinadi va Merge Request yaratiladi.

2. Sharh qoldiriladi

Jamoa a'zolari kodni satrma-satr ko'radi, fikr yozadi.

3. Tuzatiladi

Muallif sharhni inobatga olib, kodni yangilaydi.

4. Approve va merge

Tasdiqlangach, kod asosiy branchga qo'shiladi.

Pipeline: ketma-ket avtomatik bosqichlar

Pipeline sozlash: .gitlab-ci.yml (namuna)


stages:
  - build
  - test
build_job:
  stage: build
  script:
    - ./gradlew assembleDebug
test_job:
  stage: test
  script:
    - ./gradlew test

O'quv namunasi: bosqichlar (stages) ketma-ket ishlaydi.
