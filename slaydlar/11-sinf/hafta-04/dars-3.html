01

JSON tuzilmasi va Kontrakt dizayni

Universal ma'lumot formati va uning arxitektura qoidalari

JSON'ning 6 ta ma'lumot turi

Oddiy (Primitive) turlar

  • String: "Clean Code" (qo'shtirnoq shart!)
  • Number: 150000 yoki 19.99 (float/int bitta)
  • Boolean: true / false (kichik harfda)
  • Null: null (mavjud emaslik)

Murakkab (Complex) turlar

  • Object (Lug'at): {"id": 1, "name": "Ali"}
  • Array (Massiv): ["kitob", "qalam"]

Eslatma: Python'dagi None → JSON'da null, True → true bo'ladi.

Professional API Kontrakti qoidalari

Sana va Vaqt: ISO-8601 UTC

Hech qachon lokal vaqt yoki formatlanmagan string yubormang:

"created_at": "2026-10-05T08:30:00Z"

Mijoz uni o'z vaqt zonasiga o'zi o'tkazib oladi.

Pul birliklari: Butun son (Integer)

Float hisob-kitoblarda xatolik beradi (0.1 + 0.2 != 0.3):

"amount_cents": 15000000

150 000 so'm tiyinlarda yoki eng kichik birlikda saqlanadi.

02

Yagona Xatolik Konverti (Error Envelope)

Har qanday xatolikda mijoz tushunadigan standart javob formati

Error Envelope standarti

{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Kiritilgan ma'lumotlarda xatolik bor.",
    "details": [
      {
        "field": "email",
        "issue": "Email formati noto'g'ri."
      },
      {
        "field": "price",
        "issue": "Narx 0 dan katta bo'lishi shart."
      }
    ]
  }
}

Paginatsiya (Sahifalash) javobi

{
  "data": [
    {"id": 21, "title": "Clean Code", "author": "R. Martin"},
    {"id": 22, "title": "Design Patterns", "author": "GoF"}
  ],
  "meta": {
    "limit": 10,
    "offset": 20,
    "total_items": 142,
    "total_pages": 15,
    "current_page": 3
  }
}

Paginatsiya: offset yoki cursor?

?limit=20&offset=40

Sodda, kichik hajm uchun yetarli. Lekin ro‘yxatga yangi yozuv qo‘shilsa, sahifalar «suriladi».

?cursor=...

Javobda next_cursor keladi. Katta va tez o‘zgaruvchan oqimlarda barqarorroq.

Filtr: status=paid, saralash: sort=-created_at (minus - teskari).

Bashorat qiling

So‘rovda title yo‘q, year esa matn. Server nima qaytarishi kerak?

Mijoz xatosi - 4xx. Yagona konvert: code, message, details. Stack trace mijozga chiqmaydi.
03

API Xavfsizligi va Himoya choralari

Autentifikatsiya, CORS, Rate Limit va maxfiy ma'lumotlarni yashirish

401 Unauthorized vs 403 Forbidden

401 Unauthorized

«Siz kimsiz?» — So'rovda token yoki login ma'lumotlari yo'q, yaroqsiz yoki muddati o'tgan.

Authorization: Bearer <token>

403 Forbidden

«Sizga mumkin emas!» — Server sizning kimligingizni biladi, lekin bu amalga (masalan admin paneliga) ruxsat yo'q.

CORS va Rate Limiting (429)

CORS (Cross-Origin Resource Sharing)

Brauzer xavfsizligi: boshqa domen (masalan frontend.uz) sizning API (api.uz) ga murojaat qila olishini boshqarish.

Access-Control-Allow-Origin: https://frontend.uz

Rate Limiting — 429

DDoS va suiiste'mollikdan himoya: bitta IP yoki foydalanuvchiga daqiqasiga 60 ta so'rov chegarasi.

429 Too Many Requests (Retry-After: 30)

Katta xavf: Maxfiy maydonlar chiqib ketishi

# XATOLIK: Barcha maydonlarni to'g'ridan-to'g'ri qaytarish
def get_user_bad(user):
    return user.__dict__  # password_hash, salt, sirlar chiqib ketadi!

# TO'G'RI: Faqat xavfsiz ochiq maydonlarni tanlab JSON qilish (DTO)
def get_user_secure(user):
    return {
        "id": user.id,
        "username": user.username,
        "email": user.email,
        "created_at": user.created_at.isoformat()
    }
