Branch buyruqlari


# yangi tarmoq ochish va unga o'tish
git switch -c feature/add-login

# eski sintaksis (xuddi shu)
git checkout -b feature/add-login

# ro'yxat va asosiy tarmoqqa qaytish
git branch ; git switch main

# ishi bitgan tarmoqni o'chirish
git branch -d feature/add-login

Git Flow, GitHub Flow, Trunk-based development

Git Flow: 5 ta rol

Tarmoq nomini bosing: vazifasi chiqadi. Qachon: relizlari kam, qat'iy sinovli tizimlar (antivirus, tibbiyot, bank).

GitHub Flow: 5 qadam

Trunk-based development

Uzoq yashovchi branch yo'q: hamma kuniga bir necha marta kichik commit bilan asosiy tarmoqqa qo'shiladi.
  • Model Google va Meta kabi yirik jamoalarda ishlaydi
  • Tez CI/CD uchun juda mos
  • Chala funksiyalar Feature Flags bilan yashiriladi

Qaysi strategiya qachon?

Git Flow

Relizlari kam, qat'iy sinov: antivirus, bank, tibbiy tizim.

GitHub Flow

Veb-loyiha va startap: bitta main, qisqa branchlar, tez deploy.

Trunk-based

Yuqori tezlikdagi CI/CD, kuniga ko'p integratsiya, Feature Flags.

Mini-test

Commit madaniyati

Atomik commit va Conventional Commits

Atomik commit

3 kun, 40 fayl, 1 commit

«ishlar qilindi va xatolar tuzatildi». Qaysi commit nimani buzganini topib bo'lmaydi, revert qilish xavfli.

Bitta commit, bitta fikr

Har commit tugallangan mantiqiy o'zgarish. Testlar har commitdan keyin ishlaydi, orqaga qaytarish oson.

bitta fikrloyiha buzilmaydioson revert

Conventional Commits anatomiyasi

Qismni bosing: ma'nosi chiqadi. Format: type(scope): description

Asosiy turlar

feat

Yangi imkoniyat

fix

Xatoni tuzatish

docs

Faqat hujjat

chore

Build, paketlar

Yana 4 tur pastda ↓

Qolgan turlar

style

Formatlash, mantiq o'zgarmaydi

refactor

Yangi funksiya ham, xato ham yo'q, kod tozalanadi

perf

Tezlik yoki xotira

test

Testlar qo'shish

4 ta qoida

  1. Birinchi qator 50 belgidan oshmasin
  2. Fe'l buyruq maylida: add, fix (added emas)
  3. Birinchi qator oxirida nuqta yo'q
  4. Orqaga moslik buzilsa: feat!:
Breaking change: v1.4.2 dan v2.0.0 ga o'tish signali (SemVer).
