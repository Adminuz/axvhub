Review etikasi

Bu kim aqlliroq ekanini isbotlash musobaqasi emas

Kodni tanqid qiling, shaxsni emas

Noto'g'ri

To'g'ri

«Bu sikl katta ro'yxatlarda sekinlashishi mumkin. Keling, uni lug'at (hashmap) orqali O(1) tezlikka keltiramiz.»
Dalil va taklif bor: sharh hujum emas, hamkorlik.

Buyruq emas, savol bering

Noto'g'ri

«Bu funksiyani 3 ga bo'l!»
VS

To'g'ri

«Funksiya 80 qatordan oshibdi. Testlash osonroq bo'lishi uchun 2 ta kichik funksiyaga ajratsak qanday qaraysiz?»

Sabab keltiring. Yaxshi yechimni ham maqtang. Pastga ↓

Maqtashni unutmang

«Ajoyib yechim, menga juda yoqdi!»

Review faqat xato topish emas. Nafis algoritm yozgan hamkasbga shunday sharh qoldiring.

Psixologik xavfsizlik

  • Dasturchi kodiga o'z farzandidek bog'lanadi
  • Keskin sharh g'ururga tegadi va tushkunlikka soladi
  • So'zni to'g'ri tanlash texnik bilimdan kam emas

Mini-test: qaysi sharh yaxshi?

Hamkasbingiz sekin sikl yozgan. Qaysi sharh professional?

To'g'ri: sabab bor, shaxs emas kod tahlil qilinadi, taklif hamkorlik ohangida.

Reviewer uchun 5 ta savol

  1. Mantiq: kod vazifani to'g'ri bajaryaptimi?
  2. Chekka holatlar: bo'sh ro'yxat, nol, xato parol
  3. Xavfsizlik: ochiq parol yoki shifrlanmagan ma'lumot yo'qmi?
  4. O'qilishi: 6 oydan keyin tushunish oson bo'ladimi?
  5. Testlar: unit testlar qo'shilganmi?
03

Blocker va Nitpick

Pashshadan fil yasamang: jiddiylikni ajrating

Sharhning jiddiylik darajasi

Qismlarni bosing: izoh chiqadi.

Misollar: qaysi biri qaysi?

Tuzatish majburiy

  • Tizim qulashiga olib keladigan xato
  • Token ochiq qolgan (xavfsizlik)
  • Biznes mantiq noto'g'ri ishlaydi
  • Testlar yo'q

Ixtiyoriy, `nit:` bilan

  • O'zgaruvchini boshqacha atash
  • Ortiqcha bitta bo'sh qator
  • Shaxsiy ta'bga bog'liq mayda uslub

Mini-test: Blocker yoki Nitpick?

Login funksiyasi bo'sh parolda server 500 xatosi berib qulaydi. Bu nima?

To'g'ri: server qulashi kritik xato, tuzatilmaguncha merge qilib bo'lmaydi.

05

Branch Protection

Hatto jamoa sardori ham main ni xato bilan buza olmaydi

Himoyalangan main

Qismlarni bosing. Pastki yo'l main ga yopiq.

Push rad etiladi


git push origin main
remote: error: GH006: Protected branch update failed
remote: for refs/heads/main.
Xato matnida GH006 kodini ko'rasiz: bu himoya ishlayotganining belgisi.

Sozlash: qadam-baqadam

1. Settings, Branches

Repo ichida Settings, chap menyudan Branches, so'ng qoida qo'shish.

2. Branch name pattern

Maydonga main deb yozing.

3. Require a pull request

To'g'ridan-to'g'ri git push origin main butunlay bloklanadi.

4. Require approvals

Kamida 1 nafar (yoki 2) boshqa muhandis Approve bosmaguncha Merge nofaol.

5. Status checks, Save

CI testlari o'tmaguncha merge taqiqlanadi. Keyin Save changes.

Hatto xo'jayin ham buza olmaydi

«Do not allow bypassing the above settings»
  • Professional kompaniyalarda bu band yoqiladi
  • Repo egasi ham kamida bitta muhandis tasdig'isiz main ga kod qo'sha olmaydi

Amaliy topshiriq 20 daqiqa

OsonSQL kodiga xavfsizlik sharhi yozing: "... name = '" + user_input + "'"
