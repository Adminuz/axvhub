Savol 1/10

Code Review nima?

Bu xatolarni erta topish, xavfsizlik, bilim almashish va kod tozaligi uchun kerak.

Savol 2/10

Code Review etikasining asosiy qoidasi qaysi?

Yaxshi yechimlarni ham maqtash kerak: «Ajoyib yechim».

Savol 3/10

Blocker qaysi holatga tegishli?

Xavfsizlik zaifligi, tizim qulashi, noto'g'ri biznes mantiq va testlar yo'qligi — Blocker.

Savol 4/10

Nitpick sharhi qanday yoziladi?

Nitpick muallif ixtiyorida qoladi, mayda uslub masalalari uchun.

Savol 5/10

Review yakunidagi 3 qaror qaysi?

Comment bloklamaydi, Approve mergega ruxsat, Request changes tuzatishni talab qiladi.

Savol 6/10

GitHub'dagi «Commit suggestion» nima beradi?

Reviewer suggestion bloki yozadi, muallif lokal kodlamasdan qabul qiladi.

Savol 7/10

Branch Protection Require a pull request before merging yoqilsa nima bo'ladi?

Terminalda push qilinsa GH006: Protected branch update failed xatosi chiqadi.

Savol 8/10

Require status checks to pass nima talab qiladi?

Bu avtomatik sifat darvozasi.

Savol 9/10

Hamkasbingiz kodida SQL so'rovi satr qo'shish bilan tuzilgan. Qanday sharh professional?

Konstruktiv sharh sabab va aniq yechim beradi, shaxsga emas, kodga qaratiladi.

Savol 10/10

Login funksiyasi bo'sh parolda 500 xato bilan qulaydi, bundan tashqari argument nomi x. Review'da qanday tasnif qilinadi?

Tizim qulashi tuzatilishi shart, nomlash esa ixtiyoriy maslahat.

10 dan 9+

A'lo. Mavzu yaxshi o'zlashtirilgan.

Yaxshi. Xato qilgan savollar izohini qayta o'qing.

5 va undan kam

Konspekt va slaydlarni takrorlang, so'ng testni qayta yeching.
