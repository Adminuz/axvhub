Savol 1/10

Pull Request (PR) nima?

PR — muhokama maydoni, sifat eshigi va loyiha tarixi.

Savol 2/10

Professional PR qaysi savollarga javob beradi?

Nima o'zgardi, nega kerak, qanday yechildi. UI bo'lsa skrinshot, backend bo'lsa log yoki test natijasi.

Savol 3/10

PR tavsifidagi Closes #14 nima qiladi?

Closes/Fixes bog'langan issue'ni yopadi.

Savol 4/10

PR shablon fayli qayerda joylashadi?

Shablon yangi PR ochilganda tavsif oynasiga avtomatik chiqadi.

Savol 5/10

Squash and merge nima qiladi?

Asosiy tarmoq tarixi toza va chiziqli bo'ladi.

Savol 6/10

Qaysi merge usulida merge commit hosil bo'lmaydi va commitlar main oxiriga birma-bir ko'chiriladi?

Oddiy merge'da Merge branch ... commiti paydo bo'ladi; rebase commitlarni ko'chirib ulaydi.

Savol 7/10

Merge conflict qachon yuzaga keladi?

Git qaysi variant to'g'riligini o'zi hal qilolmaydi va yordam so'raydi.

Savol 8/10

Konfliktni hal qilish ketma-ketligi qaysi?

Ikkala mantiq to'g'ri birlashtiriladi, <<<<<<<, =======, >>>>>>> belgilari olib tashlanadi.

Savol 9/10

PR'ga nega dalil (skrinshot yoki log) qo'shiladi?

UI uchun oldin/keyin skrinshoti, backend uchun test natijasi yoki terminal logi.

Savol 10/10

app.txt da main va feature shoxlari bir qatorni turlicha o'zgartirdi. git merge feat/update-text dan keyin nima chiqadi?

Avtomatik birlashtirish bajarilmaydi; konfliktni qo'lda hal qilib, commit bilan yakunlaysiz.

Natijangiz

10 dan 9+

A'lo. Mavzu yaxshi o'zlashtirilgan.

10 dan 6-8

Yaxshi. Xato qilgan savollar izohini qayta o'qing.

5 va undan kam

Konspekt va slaydlarni takrorlang, so'ng testni qayta yeching.

Takrorlang: PR anatomiyasi (What/Why/How), PR shabloni, merge strategiyalari, merge conflict.
