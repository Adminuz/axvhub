11-sinfProfessional IT development2-hafta

Savol 1/10

Git'da branch (tarmoq) texnik jihatdan nima?

Branch og'ir nusxa emas, shuning uchun uni ochish millisekundlarda bajariladi.

Savol 2/10

Jamoada har bir yangi vazifa nega alohida branchda bajariladi?

Yarim tayyor kod main ga tushmasa, sayt qulamaydi va mijozga xom kod yetmaydi.

Savol 3/10

Qaysi buyruq yangi tarmoq yaratib, unga o'tadi?

switch -c zamonaviy sintaksis; checkout -b unga ekvivalent eski usul.

Savol 4/10

Git Flow'dagi hotfix/* tarmog'i qachon ochiladi?

Hotfix main dan ochiladi va ham main ga, ham develop ga merge qilinadi.

Savol 5/10

GitHub Flow'ning asosiy qoidasi qaysi?

GitHub Flow — yengil model: main, feature branch, PR, review, merge va deploy.

Savol 6/10

Trunk-based Development'da chala funksiyalar foydalanuvchiga ko'rinmasligi uchun nima ishlatiladi?

Kod trunk'ga kunda bir necha marta integratsiya qilinadi, chala qism flag orqali o'chirib qo'yiladi.

Savol 7/10

Conventional Commits'da foydalanuvchi uchun yangi funksiyani bildiruvchi tur qaysi?

feat yangi funksionallik, fix xato tuzatish, docs hujjat, chore yordamchi o'zgarishlar.

Savol 8/10

Quyidagi commit xabarlaridan qaysi biri qoidaga mos?

Fe'l buyruq maylida (add, fix), birinchi qatorda oxirida nuqta yo'q, tur ko'rsatilgan.

Savol 9/10

refactor: va fix: farqi nima?

Refactor na funksiya qo'shadi, na xato tuzatadi, faqat kod tuzilishini yaxshilaydi.

Savol 10/10

Siz 3 kun ishlab, 40 fayl o'zgartirdingiz va bitta commit qilmoqchisiz: «ishlar qilindi». Nima xato va qanday to'g'rilanadi?

Bitta commit — bitta mantiqiy o'zgarish. Aks holda qaysi commit nimani buzganini topib bo'lmaydi va revert qiyinlashadi.

Natijangiz

10 dan 9+

A'lo. Mavzu yaxshi o'zlashtirilgan.

10 dan 6-8

Yaxshi. Xato qilgan savollar izohini qayta o'qing.

5 va undan kam

Konspekt va slaydlarni takrorlang, so'ng testni qayta yeching.

Takrorlang: branch tushunchasi, Git Flow, GitHub Flow, Trunk-based, Conventional Commits va atomik commit.
