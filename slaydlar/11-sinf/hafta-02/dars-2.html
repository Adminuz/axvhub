Qachon qaysi biri?

Squash

Odatiy zamonaviy standart: feature kichik va toza

Merge commit

Katta subsystem relizlari, Git Flow'da develop ni main'ga qo'shish

Rebase

Tarix qat'iy chiziqli bo'lishini xohlovchi jamoalar

Merge conflict qanday ko'rinadi?

Yuqori va pastki blokni bosing.

Konfliktli fayl


<<<<<<< HEAD
host = "localhost"
=======
host = "127.0.0.1"
>>>>>>> feat/network

Yechilgan fayl


host = "127.0.0.1"
Belgilar o'chirildi: endi git add va git commit.

Konfliktni yechish: 4 qadam

1. Muharrirda oching

VS Code yoki boshqa muharrirda konfliktli faylga qarang.

2. Mantiqni tanlang

Ikkala qismni tahlil qiling va to'g'ri kodni belgilang.

3. Belgilarni o'chiring

<<<<<<<, =======, >>>>>>> qatorlarini qo'lda olib tashlang.

4. add va commit

git add fayl, so'ng git commit: merge yakunlanadi.

Konflikt laboratoriyasi


git switch -c feat/update-text
echo "Versiya 2.0 - feature" > app.txt
git commit -am "feat: update line"
git switch main
echo "Versiya 1.5 - main" > app.txt
git commit -am "fix: hotfix on main"
git merge feat/update-text
# CONFLICT (content): Merge conflict in app.txt
echo "Versiya 2.0 - kelishuv" > app.txt
git add app.txt
git commit -m "merge: resolve conflict"

GitHub'dagi toza PR

github.com/org/repo/pull/24

feat(auth): add google oauth login #24

Open · dev wants to merge 3 commits into main from feat/auth

Why: Closes #14 · What: login tugmasi, callback · Checks: 2 successful

Tezkor savol

Feature'dagi 10 ta commit main'ga bitta toza commit bo'lib tushishi uchun qaysi strategiya tanlanadi?

To'g'ri: Squash and merge barcha commitlarni bitta toza commitga siqadi va main tarixini tartibli saqlaydi.
