03

Repozitoriy, 3 zona, commit

Git ishining asosiy sikli

git init: .git/ hosil bo'ladi

.git/ ni o'chirsangiz, butun tarix yo'qoladi. Fayllar qoladi, lekin Git ularni endi bilmaydi.

Uch zona modeli

Zonaning ustiga olib boring yoki bosing.

Birinchi commit


$ mkdir dev-journal && cd dev-journal
$ git init -b main
Initialized empty Git repository in .../dev-journal/.git/
$ echo "# Dev Journal" > README.md
$ git status -s
?? README.md
$ git add README.md
$ git commit -m "docs: add README"
[main (root-commit) bd42656] docs: add README
 1 file changed, 1 insertion(+)

?? = kuzatilmayapti (untracked). A = stagingda. Qator-qator tushuntiring.

git status -s: belgilarni o'qing

??

bosing

Yangi, Git kuzatmaydi

A

bosing

Yangi fayl stagingga qo'shildi

_M

bosing

O'zgardi, hali stagingda emas

M_

bosing

O'zgardi va stagingda


$ git diff            # ishchi papka va staging farqi
$ git diff --staged   # staging va oxirgi commit farqi

Commit xabari: avval


$ git commit -m "ozgardi"
Nima o'zgardi? Nega? 3 oydan keyin o'zingiz ham eslay olmaysiz.

Commit xabari: keyin


$ git commit -m "feat: add greeting by name"

Conventional Commits: tur: qisqa tavsif. Buyruq maylida, 50 belgigacha.

O'zgartirdik, ko'rdik, saqladik


$ echo 'print("Ikkinchi qator")' >> hello.py
$ git diff

+++ b/hello.py
@@ -1 +1,2 @@

+print("Ikkinchi qator")

$ git log --oneline

-a faqat allaqachon kuzatilayotgan fayllarni oladi. Yangi fayl uchun avval git add.
04

Branch, merge va tarix

Asosiy shoxga tegmasdan xavfsiz tajriba

Branch — mustaqil yo'lak

Branch — commit'ga ko'rsatkich (yorliq). Yaratish deyarli bepul va bir lahzada bo'ladi.

Shox ochamiz, ishlaymiz, qaytamiz


$ git switch -c feature/greeting
Switched to a new branch 'feature/greeting'
$ git commit -am "feat: greet by name"
[feature/greeting 245556f] feat: greet by name
$ git switch main
Switched to branch 'main'
$ git merge feature/greeting
Updating 3280c5a..245556f
Fast-forward
 hello.py | 4 ++--
$ git branch -d feature/greeting

Merge ikki xil bo'ladi

Konflikt: Git to'xtab, so'raydi


$ git merge feature/title
Auto-merging README.md
CONFLICT (content): Merge conflict in README.md
$ cat README.md
<<<<<<< HEAD
# Dasturchi kundaligi
=======
# Aziz Dev Journal
>>>>>>> feature/title

Bitta qatorni ikki shox turlicha o'zgartirgan. Pastga ↓ yechish tartibi

Konfliktni yechish

1. O'qing

Faylni oching, ikkala variantni o'qing

2. Tahrirlang

Qoldiradigan matnni yozing, <<< === >>> belgilarini o'chiring

3. Stagingga

git add README.md

4. Commit

git commit (merge'ni yakunlaydi)

Qo'rqmang: git merge --abort hammasini merge'dan oldingi holatga qaytaradi.

Tarixni o'qing: git log


$ git log --oneline --graph
*   79a25f9 Merge branch 'feature/bye'
|\
| * 03c5311 feat: add goodbye
* | d76ee7f docs: describe project
|/
* 245556f feat: greet by name
* 3280c5a feat: add second line
--oneline--graph--all-n 5git show <hash>

Xato qildim: qanday qaytaraman?

Ishchi o'zgarish

git restore hello.py
faylni oxirgi commit holatiga

Stagingdan olish

git restore --staged hello.py
fayl o'zgarishi saqlanadi

Commitni bekor

git revert <hash>
teskari commit, tarix buzilmaydi

git restore saqlanmagan o'zgarishni qaytarib bo'lmaydigan qilib o'chiradi.

Odatiy xatolar

Parolni commit qilish

Tarixdan o'chirish juda qiyin. Maxfiy fayllarni .gitignore ga yozing.

Noto'g'ri shoxda ishlash

Ish boshlashdan oldin git branch yoki git status.

git add . ko'r-ko'rona

Keraksiz fayl (node_modules, .env) tushadi. Avval status.

«fix» kabi xabar

Tarix foydasiz bo'lib qoladi. Nima va nega ekanini yozing.

Tezkor savol

hello.py ni o'zgartirdingiz, git add qilmadingiz va git commit -m "x" yozdingiz. Commitga nima tushadi?

To'g'ri: «nothing added to commit». Faqat stagingdagilar commitga tushadi. Variant: git commit -am kuzatiladigan faylni o'zi stagingga oladi.
