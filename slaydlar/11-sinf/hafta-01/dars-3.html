01

Lokal Git dan GitHub gacha

Nega tarix faqat noutbukda qolmasligi kerak

Git va GitHub bir narsa emas

Git

Kompyuteringizdagi dastur. Tarixni yuritadi: commit, status, log. Internet shart emas.
VS

GitHub

Repolarni saqlaydigan veb-xizmat. Hamkorlik: Issues, Pull Request, review, Actions.
Git — shaxsiy daftar. GitHub — shu daftarning umumiy kutubxonadagi nusxasi va muhokama doskasi.

Lokal, remote va ikkinchi nusxa

Boshlash: to'rt qadam

1. Akkaunt: o'zingiz, o'z brauzeringizda. Nomi professional bo'lsin: github.com/nom CV'dagi havola
2. 2FA: ikki bosqichli tasdiqlash. Tiklash kodlarini xavfsiz saqlang
3. Kirish usuli: SSH kalit, token yoki gh auth login
4. Bo'sh repo: dev-log, README va .gitignore belgilanmaydi
Parol, token va kodlarni hech kimga, mentorga ham, chatga ham yubormang.
02

Xavfsiz kirish

Token, SSH kalit va ularni qanday asrash kerak

Autentifikatsiya: uch yo'l

HTTPS + token

Parol o'rniga PAT. Oddiy parol bilan push bo'lmaydi

SSH kalit

Kalit juftligi. Uzoq muddatli eng qulay yo'l

gh auth login

GitHub CLI: brauzer orqali, tokenni o'zi boshqaradi

SSH: qulf va kalit

Kalit yaratish va tekshirish


ssh-keygen -t ed25519 -C "sizning@emailingiz"
cat ~/.ssh/id_ed25519.pub
ssh -T git@github.com
Faqat .pub ko'rsatiladi. Nuqtasiz fayl maxfiy: yubormang, commit qilmang, skrinshot qilmang.

Token: vaqtinchalik parol

PAT oddiy paroldan xavfsizroq: unga cheklov qo'yiladi. Qoidalar uchun pastga ↓

Token qoidalari

  1. Minimal ruxsat: faqat kerakli repo va amal
  2. Qisqa muddat qo'ying (expiration)
  3. Kodga, README'ga, chatga, skrinshotga yozmang
  4. Sizib chiqsa: darhol GitHub'da o'chiring (revoke)

Nega bu muhim?

Ochiq repolarni botlar skanerlaydi: sizib chiqqan kalit daqiqalar ichida topilishi mumkin.

Qo'llanma tamoyili: minimal vakolat (least privilege).

Remote, push, pull, clone

Birinchi commitlaringiz GitHub'ga yo'l oladi

Ulash va yuborish


git branch -M main
git remote add origin git@github.com:nom/dev-log.git
git remote -v
git push -u origin main
  • origin: masofaviy repo nomi
  • -u: keyin shunchaki git push / git pull

fetch va pull

git fetch

Yangilikni yuklab oladi. Fayllaringizga tegmaydi. git log origin/main bilan qarab olasiz.
VS

git pull

fetch + birlashtirish. Yangilik joriy shoxga qo'shiladi.
Gumon bo'lsa, avval fetch. Ritm: fetch, pull, keyin push.

Odatiy xato: push rad etildi


$ git push
 ! [rejected]  main -> main (fetch first)
error: failed to push some refs
  • Masofada sizda yo'q commit bor
  • Yechim: git pull, keyin git push
--force bilan majburlamang: boshqalarning ishini yo'qotasiz.
