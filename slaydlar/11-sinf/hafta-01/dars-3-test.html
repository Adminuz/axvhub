11-sinfProfessional IT development1-hafta

Savol 1/10

Git va GitHub o'rtasidagi farq qaysi javobda to'g'ri?

Git internet siz ishlaydi. GitHub unga Issues, Pull Request va review kabi hamkorlikni qo'shadi.

Savol 2/10

Masofaviy repoga odatiy nom nima?

origin — masofaviy repo havolasiga beriladigan odatiy nom.

Savol 3/10

git fetch va git pull farqi nima?

pull = fetch + merge. fetch ishchi fayllarni o'zgartirmaydi.

Savol 4/10

Qaysi fayl SSH kalitining ochiq qismi va GitHub'ga qo'yiladi?

.pub ochiq kalit. id_ed25519 esa maxfiy kalit, uni hech kimga yubormang.

Savol 5/10

.gitignore ga eng avval nimalarni kiritish kerak?

Sirlar tarixga kirmasligi va keraksiz chiqindilar repoga tushmasligi uchun.

Savol 6/10

Commit xabarida Closes #1 yozilsa nima bo'ladi?

GitHub Closes/Fixes kalit so'zlarini tanib, bog'langan issue'ni yopadi.

Savol 7/10

Yangi GitHub repo yaratayotganda, lokal repo allaqachon bor bo'lsa, README/.gitignore ni belgilash nega xato?

Masofada sizda yo'q commit paydo bo'ladi, shu sabab push non-fast-forward bilan rad etiladi.

Savol 8/10

.env fayli allaqachon commit qilingan. .gitignore ga qo'shish yetadimi?

Kuzatilayotgan faylni git rm --cached bilan kuzatuvdan chiqarish kerak.

Savol 9/10

Token tasodifan GitHub'ga commit bo'ldi. Birinchi qadam nima?

Tarixga tushgan sir yo'qolmaydi. Avval sirni bekor qiling, keyin tarixni tozalash haqida o'ylang.

Savol 10/10

git push rad etildi: «rejected, non-fast-forward». To'g'ri harakat qaysi?

Masofada sizda yo'q commit bor. Force push boshqalar ishini o'chirib yuborishi mumkin.

Natijangiz

10 dan 9+

A'lo. Mavzu yaxshi o'zlashtirilgan.

10 dan 6-8

Yaxshi. Xato qilgan savollar izohini qayta o'qing.

5 va undan kam

Konspekt va slaydlarni takrorlang, so'ng testni qayta yeching.

Takrorlang: Git va GitHub farqi, fetch va pull, SSH kalitlari, .gitignore, Closes # qoidasi, sirlar bilan ishlash.
