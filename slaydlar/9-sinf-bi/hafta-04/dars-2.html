03

Ma'lumotlar yaxlitligi

Aniq, to'liq va izchil

Uch tur yaxlitlik

Entity

bosing

Har qator noyob: PRIMARY KEY takrorlanmaydi va NULL bo'lmaydi.

Referential

bosing

FOREIGN KEY faqat mavjud PK qiymatiga ishora qiladi.

Domain

bosing

Qiymat ruxsat etilgan doirada: tur, NOT NULL, CHECK, DEFAULT.

Cheklovlar (constraints)

NOT NULL

Bo'sh qolmasin: ism.

UNIQUE

Takrorlanmasin: email, telefon.

CHECK

Shartga mos: Narx > 0.

DEFAULT

Standart qiymat: N'Toshkent'.

PRIMARY KEY

Noyob identifikator.

FOREIGN KEY

Boshqa jadvalga bog'lanish.

Cheklovli jadval


CREATE TABLE Mijozlar (
    MijozID INT PRIMARY KEY,
    Ism     NVARCHAR(50) NOT NULL,
    Telefon VARCHAR(20)  UNIQUE,
    Shahar  NVARCHAR(30) DEFAULT N'Toshkent',
    Yosh    INT CHECK (Yosh >= 14)
);

NVARCHAR - o'zbek harflari uchun Unicode matn; qiymat N'...' ko'rinishida.

FK bilan bog'lash


CREATE TABLE Buyurtmalar (
    BuyurtmaID INT PRIMARY KEY,
    Sana       DATE NOT NULL,
    MijozID    INT NOT NULL FOREIGN KEY REFERENCES Mijozlar(MijozID)
);
Avval Mijozlar, keyin Buyurtmalar: FK mavjud jadvalga ishora qiladi.

Xato - bu himoya

Messages
INSERT Mijozlar (1, N'Bekzod') -- ID 1 bor
Xato: PRIMARY KEY buzildi
INSERT Buyurtmalar (101, ..., 99)
Xato: FOREIGN KEY: MijozID 99 yo'q

Cheklovlar «iflos» ma'lumotni bazaga kiritmaydi - Data Cleaning ishi kamayadi.

Mini-test

Baholar jadvalida mavjud bo'lmagan FanID = 55 kiritildi. Qaysi yaxlitlik turi buzildi?

FK mavjud bo'lmagan PK qiymatiga ishora qilmoqda - referential integrity buzildi, DBMS rad etadi.

ACID

A - Atomicity

Hammasi yoki hech biri: pul yechilib, qo'shilmasa - bekor.

C - Consistency

Tranzaksiyadan keyin barcha cheklovlar saqlanadi.

I - Isolation

Bir vaqtdagi tranzaksiyalar bir-biriga xalaqit bermaydi.

D - Durability

COMMIT qilingan o'zgarish elektr o'chsa ham saqlanadi.
