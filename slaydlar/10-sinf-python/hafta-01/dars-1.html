02

Server-Side Rendering

Sahifaning serverda to'liq tayyorlanishi (Klassik Django)

SSR qanday ishlaydi?

Server ma'lumotlar bazasidan olib, HTML shablonni to'ldiradi va tayyor sahifani uzatadi

SSR ning tahlili

Afzalliklari

  • A'lo darajadagi SEO: Qidiruv botlari (Google, Yandex) to'liq HTML-ni darhol o'qiydi.
  • Tezkor birinchi ko'rinish: Foydalanuvchi sahifani bir zumda ko'radi.
  • Oddiy arxitektura: Frontend va backend bitta loyihada jamlangan.

Kamchiliklari

  • Sahifaning to'liq yangilanishi: Har bir havola bosilganda butun ekran oqarib qayta yuklanadi.
  • Server yuki yuqori: Server har bir so'rovga HTML fayl yig'ib berishi kerak.
  • Mobil ilovalar uchun yaroqsiz: iOS yoki Android ilovaga HTML kerak emas, toza ma'lumot kerak.

04

REST arxitekturasi va DRF

Standartlashtirilgan backend API tamoyillari

RESTful API ning 4 ta oltin qoidasi

  1. Client-Server ajratilganligi: Foydalanuvchi interfeysi va backend bir-biriga bog'liq bo'lmagan mustaqil tizimlar.
  2. Stateless (Holatsiz): Server har bir so'rovni mustaqil bajaradi. O'tgan so'rovlar holati sessiyada saqlanmaydi.
  3. Resurslarga asoslangan URL: URL fe'l emas, ot bo'lishi kerak: /api/v1/posts/ (amal metod bilan bildiriladi).
  4. Universal format: Ma'lumotlar platformalarga bog'liq bo'lmagan umumiy formatda (JSON) uzatiladi.

Tezkor bilim tekshiruvi

Qaysi holatda Django REST Framework (API) ishlatish eng to'g'ri qaror hisoblanadi?

To'g'ri! REST API ning eng katta kuchi — bitta yagona backend orqali barcha frontend mijozlariga (veb, mobil, bot) ma'lumot yetkazib berishidir.

Dasturchilar ko'p yo'l qo'yadigan xatolar

Xato: REST URL ichida amallarni yozish (GET /api/v1/delete_user/5/ xato!).
To'g'ri: URL faqat resurs nomi bo'lsin: DELETE /api/v1/users/5/.
