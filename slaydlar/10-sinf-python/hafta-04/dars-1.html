Authentication va Authorization

Authentication

Authorization (Permissions)

«Nima qila olasiz?»

DRF'dagi standart autentifikatsiya turlari

Basic

Login:parol Base64 da. Base64 shifrlash emas! Faqat testda.

Session

sessionid cookie. Brauzerga qulay, CSRF'ga moyil.

Token

Server tasodifiy token beradi. Mobil uchun yaxshi, lekin har so'rovda bazaga murojaat.

JWT anatomiyasi: Header.Payload.Signature

Uch qism nuqta (.) bilan ajratiladi. JWT bazaga murojaat qilmasdan o'z to'g'riligini tasdiqlaydi.

Access va Refresh token

Access token

Qisqa muddat: 5-15 daqiqa.

Har so'rovda yuboriladi. O'g'irlansa tez yaroqsiz bo'ladi.

VS

Refresh token

Uzoq muddat: 1 kundan 1 oygacha.

Faqat yangi access olish uchun ishlatiladi.

Pastga bosing: nima yozmaslik kerak

Payload sirlari

Payload ichiga parol yoki bank kartasi raqamini hech qachon yozmang: u shifrlanmagan.
JWT DRF standart paketida yo'q: djangorestframework-simplejwt o'rnatiladi.

SimpleJWT: qisqa access, uzun refresh

from datetime import timedelta

SIMPLE_JWT = {
    "ACCESS_TOKEN_LIFETIME": timedelta(minutes=10),
    "REFRESH_TOKEN_LIFETIME": timedelta(days=7),
    "ROTATE_REFRESH_TOKENS": True,
    "BLACKLIST_AFTER_ROTATION": True,
    "UPDATE_LAST_LOGIN": True,
}
INSTALLED_APPS += ["rest_framework_simplejwt.token_blacklist"]

Rotate + blacklist: refresh tokenni qayta ishlatish hujumini pasaytiradi. Keyin python manage.py migrate.

Ruxsatlar va Throttling

Nima qila olasiz? Necha marta?

Tayyor ruxsat sinflari

SinfKimga ruxsat
AllowAnyHammaga, mehmonlarga ham
IsAuthenticatedFaqat tizimga kirganlarga (aks holda 401)
IsAdminUserFaqat is_staff=True
IsAuthenticatedOrReadOnlyMehmon faqat o'qiydi (GET)

Custom permission: faqat o'z postini tahrirlash

from rest_framework.permissions import BasePermission

class IsAuthor(BasePermission):
    def has_permission(self, request, view):
        return request.user.is_authenticated

    def has_object_permission(self, request, view, obj):
        return obj.author == request.user

Egasi bo'lmasa DRF avtomatik 403 Forbidden qaytaradi. (O'quv misol.)

Throttling: so'rovlar sonini cheklash

AnonRateThrottle

Mehmonlar, IP manzil bo'yicha.

UserRateThrottle

Tizimga kirgan foydalanuvchilar.

ScopedRateThrottle

Alohida joy, masalan parolni tiklash.

Limit oshsa: 429 Too Many Requests. Throttlingsiz API brute-force va DDoS'ga ochiq.

04

CORS, CSRF va inyeksiya

Brauzer va ma'lumot himoyasi

CORS: Same-Origin Policy

Server brauzerga «react-loyiha.uz ga ruxsat beraman» deydi. Django: django-cors-headers.

CORS sozlamasi: xavfli va to'g'ri

CORS_ALLOW_ALL_ORIGINS = True
# productionda hech qachon!
CORS_ALLOWED_ORIGINS = os.getenv(
    "CORS_ALLOWED_ORIGINS", ""
).split(",")

CSRF hujumi qanday ishlaydi?

1. Siz bankka kirdingiz

Sessiya va cookie yaratildi.

2. Boshqa saytga o'tdingiz

Haker sahifasida yashirin forma bor.

3. Brauzer cookie yuboradi

Bank so'rovni qonuniy deb o'ylaydi!

4. Yechim: CSRF token

Har POST/PUT da tasodifiy token; haker uni bilmaydi.

Faqat JWT/Token ishlatsangiz CSRF muammo emas: brauzer tokenni o'zi yubormaydi.

Foydalanuvchi ma'lumotiga ishonmang

Never trust user input: foydalanuvchi yuborgan ma'lumotga hech qachon ishonmang.
name = "'; DROP TABLE users; --"
# qo'lda SQL ga yopishtirish: bazani o'chiradi

Serializer tekshiradi, ORM xavfli belgilarni zararsizlantiradi. Raw SQL dan qoching. XSS: izohga JavaScript yozish.

Security checklist

Konfiguratsiya

DEBUG=False, ALLOWED_HOSTS, .env (sir kodda emas).

Transport

HTTPS, secure cookies, HSTS, faqat kerakli CORS originlar.

Auth va limit

JWT access qisqa, refresh rotate+blacklist, login throttling.

Fayl va log

Upload: MIME va hajm limiti; logging, security headers.

Mini-test

Foydalanuvchi qaysi tokenni har so'rovda yuboradi va u nega qisqa yashaydi?

Access token qisqa muddatli (5-15 daqiqa) va har so'rovda yuboriladi; refresh faqat yangilash uchun.

Odatiy xatolar

Payload'ga parol yozish; productionda CORS_ALLOW_ALL_ORIGINS = True; DEBUG = True qoldirish.
SECRET_KEY va DB parolini GitHub'ga yuklash; login uchun throttling qo'ymaslik.
To'g'ri: sirlar .env da, kerakli CORS originlar, qisqa access token, serializer validatsiyasi.
