10-sinfAdvanced Python Back-end4-hafta

Savol 1/10

API xavfsizligida «Authentication» qaysi savolga javob beradi?

Authentication kimligini aniqlaydi; ruxsatlar (Permissions) esa nima qila olishini belgilaydi.

Savol 2/10

Nima uchun Basic Authentication productionda ishlatilmaydi?

Base64 shunchaki kodlash: HTTPS bo'lmasa parol oson o'qiladi.

Savol 3/10

JWT ning uchta qismi qaysi javobda to'g'ri tartibda?

Qismlar nuqta bilan ajratiladi: Header.Payload.Signature.

Savol 4/10

JWT Payload qismi haqida qaysi gap to'g'ri?

Payload ichiga parol yoki karta raqamini yozmang.

Savol 5/10

Access token nega qisqa muddatli bo'ladi?

Access 5-15 daqiqa yashaydi, har so'rovda yuboriladi.

Savol 6/10

Foydalanuvchi tizimga kirgan, lekin boshqa odamning postini PATCH qilmoqchi. DRF qaysi status qaytaradi?

Kimligi ma'lum, lekin ruxsati yo'q: 403. 401 esa kimligi noma'lum bo'lganda.

Savol 7/10

has_object_permission metodi nimani tekshiradi?

URL ga kirish: has_permission; aniq obyekt: has_object_permission.

Savol 8/10

Production uchun qaysi CORS sozlamasi to'g'ri?

Hamma domenga ruxsat berish xavfli; aniq originlar .env dan o'qiladi.

Savol 9/10

Faqat JWT ishlatiladigan API da CSRF himoyasi nega muammo emas?

CSRF cookie ning avtomatik yuborilishiga tayanadi; token esa Authorization headerga qo'lda qo'shiladi.

Savol 10/10

Login endpoint uchun nega login_anon: 5/min kabi qat'iy limit qo'yiladi?

Bot sekundiga minglab parolni sinab ko'rishi mumkin; limit oshsa 429 qaytadi.

Natijangiz

10 dan 9+

A'lo. Mavzu yaxshi o'zlashtirilgan.

10 dan 6-8

Yaxshi. Xato qilgan savollar izohini qayta o'qing.

5 va undan kam

Konspekt va slaydlarni takrorlang, so'ng testni qayta yeching.

Takrorlang: Authentication/Authorization, JWT, Access/Refresh, permissions, throttling 429, CORS/CSRF.
