10-sinfAdvanced Python Back-end2-hafta

Savol 1/10

Foydalanuvchi saytga o'z emailini kiritib «Mening emailim ali@mail.uz» dedi. Bu qaysi tushuncha?

Identifikatsiya «Siz kimsiz?» savoliga javob: login yoki email.

Savol 2/10

Kiritilgan parol bazadagi shifrlangan hesh bilan solishtirilmoqda. Bu qaysi bosqich?

Autentifikatsiya shaxsning haqiqiyligini tekshiradi: «Haqiqatan ham sizmisiz?».

Savol 3/10

«Ali oddiy foydalanuvchi, u boshqa birovning maqolasini o'chira olmaydi» qaysi tushunchaga misol?

Avtorizatsiya foydalanuvchining qaysi amallarga huquqi borligini aniqlaydi.

Savol 4/10

JWT nuqta bilan ajratilgan qaysi 3 qismdan iborat?

JWT ko'rinishi xxxxx.yyyyy.zzzzz: sarlavha, ma'lumotlar va raqamli imzo.

Savol 5/10

Himoyalangan endpointga JWT access token qaysi sarlavhada yuboriladi?

Access token har bir API so'rovida Authorization: Bearer ... shaklida yuboriladi.

Savol 6/10

Refresh token nima uchun kerak?

Refresh uzoq yashaydi va foydalanuvchini har safar qayta parol terishga majburlamaydi.

Savol 7/10

Session asosidagi autentifikatsiyaning asosiy kamchiligi nima?

Session serverda saqlanadi (stateful), tokenni bekor qilish esa oson bo'ladi.

Savol 8/10

Nega standart Django User o'rniga Custom User yaratish tavsiya etiladi?

Custom User AbstractBaseUser va PermissionsMixin asosida loyiha boshidanoq yaratiladi.

Savol 9/10

USERNAME_FIELD = "email" va email = models.EmailField(unique=True) birgalikda nimani bildiradi?

USERNAME_FIELD login sifatida ishlatiladigan maydonni belgilaydi, unique=True esa takrorlanishni taqiqlaydi.

Savol 10/10

Xaker JWT payload'ini o'zgartirib, user_id ni 1 ga almashtirdi, imzoni o'zgartirmadi. Nima bo'ladi?

Signature server SECRET_KEY bilan Header va Payload'dan hosil qiladi; o'zgartirilsa imzo mos kelmaydi.

10 dan 9+

A'lo. Mavzu yaxshi o'zlashtirilgan.

10 dan 6-8

Yaxshi. Xato qilgan savollar izohini qayta o'qing.

5 va undan kam

Konspekt va slaydlarni takrorlang, so'ng testni qayta yeching.
